# AI Business OS — Retention Model v1.0

**Status:** Strategic foundation  
**Date:** 2026-06-28  
**Question this document answers:** *Why does a customer come back tomorrow, next week, and next month?*

**Related:** [Customer Journey](./CUSTOMER_JOURNEY.md) · [Pricing Strategy](./PRICING_STRATEGY.md) · [Metrics](./METRICS.md)

---

## Retention thesis

Users stay when the platform becomes the **default place to turn goals into finished business work**. Retention is not driven by AI novelty. It is driven by **accumulated results, continuity, and trusted recommendations**.

If a user can answer "What should I do next for my business?" on the platform faster than anywhere else, they return.

---

## Why return tomorrow?

| Reason | Product mechanism | Emotional hook |
| ------ | ----------------- | -------------- |
| **Unfinished momentum** | Result ends with "What's next?" | "I know the next step" |
| **Saved context** | Projects + history remember prior work | "It didn't forget me" |
| **Low re-entry cost** | Continue previous work on Home | "One tap to resume" |
| **Curiosity** | Personal welcome with recommendation | "It has a suggestion for me" |

### Tomorrow test

After every result, the user must leave with **one clear next action** — not a blank screen.

---

## Why return next week?

| Reason | Product mechanism | Emotional hook |
| ------ | ----------------- | -------------- |
| **Weekly business rhythm** | Goals map to real jobs (clients, revenue, content) | "Monday planning lives here" |
| **Growing asset** | History of completed results | "My work is piling up here" |
| **Trust compound** | Intent confirmation was right last time | "It understands my business" |
| **Project depth** | Multiple threads in projects | "This is my operating hub" |

### Weekly habit target

**≥ 1 completed result per week** = retained user  
**≥ 2 completed results per week** = power user (expansion candidate)

---

## Why return next month?

| Reason | Product mechanism | Emotional hook |
| ------ | ----------------- | -------------- |
| **Business progress narrative** | Month of results + recommendations | "I moved forward" |
| **Switching cost** | Projects, history, learned context | "Starting over elsewhere hurts" |
| **Paid commitment** | Subscription aligned to results used | "I'm getting value for money" |
| **Vertical depth** | Packs and playbooks improve over time | "It gets better for my industry" |

### Monthly retention target

**D30 ≥ 40%** for users who completed first result within 7 days of signup (benchmark to validate).

## The habit loop

Adapted from Hook Model — applied to business outcomes, not dopamine tricks.

```text
        ┌──────────────────────────────────────┐
        │                                      │
        ▼                                      │
   TRIGGER          ACTION           REWARD
 (business need)  (choose goal)   (completed result)
        │              │                │
        │              ▼                │
        │         INVESTMENT            │
        │    (save to project,          │
        │     accept recommendation)    │
        └────────────────────────────────┘
```

### 1. Trigger

| Type | Example |
| ---- | ------- |
| **External** | Email: "Continue Client Acquisition"; calendar Monday |
| **Internal** | Anxiety about pipeline; need for content this week |
| **Product** | Home recommendation: "Today I'd recommend continuing…" |

### 2. Action

Minimum viable action: **select a goal** (or tap Continue).  
Friction must stay below opening a doc, a chat thread, or hiring help.

### 3. Variable reward

- Useful deliverable (plan, draft, analysis)
- Surprise quality moment (Wow + celebration on milestones)
- Recommendation that feels personally right

*Variable* means outcome type changes; **quality** must stay consistently high.

### 4. Investment

| Investment | Why it increases retention |
| ---------- | --------------------------- |
| Save to project | Data and context live in platform |
| Accept "What's next?" | Trains loop for next session |
| Create project #2 | Organizational commitment |
| Upgrade tier | Financial commitment |

## Retention loops by lifecycle

### Loop A — Daily micro (power users)

```text
Open Today → Continue work → Complete result → What's next → Leave
```

### Loop B — Weekly planning (primary target)

```text
Monday open → Smart greeting → New goal → Intent → Result → Project update
```

### Loop C — Return after absence

```text
Email / memory → Personal welcome → Yesterday's work recap → Recommended goal
```

## Anti-churn signals

| Signal | Risk | Intervention |
| ------ | ---- | ------------ |
| No login 7 days after first result | Cooling | "Your plan is ready to continue" |
| Intent abandoned | Confusion | Simplify goal; offer "Help me decide" |
| Failed result | Trust break | Human retry + support |
| Hit cap without upgrade | Value proven | Upgrade offer with summary |
| No project after 3 results | Shallow use | Prompt to organize in project |

---

## Retention vs engagement

| Engagement (vanity) | Retention (business) |
| ------------------- | -------------------- |
| Logins | Weekly Active Businesses with ≥1 result |
| Messages sent | Completed business outcomes |
| Time in app | Results used (export, copy, project save) |
| Features clicked | Recommendation acceptance |

Optimize for **outcomes per active business per week**.

---

## Paid retention

Users pay when:

1. Free/trial limit arrives **after** they felt value
2. Upgrade removes friction (more projects, team, history)
3. Bill is predictable and explainable in business terms

Churn drivers to eliminate:

- Surprise charges
- "Empty" results
- No reason to return (missing What's next)
- Product feels like beta / mixed language

## Success definition

Retention model works when:

- **> 50%** of first-result users return within 7 days
- **> 35%** return within 30 days
- **Recommendation acceptance** rises over time (trust compound)
- **Expansion revenue** grows from retained cohorts, not new acquisition alone
